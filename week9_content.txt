Week 9 — App Deployment & Go-Live 
1. Overview of the Week 
This is the week your app becomes real. You take everything from localhost and deploy it to the public internet. The frontend goes to Vercel, the backend goes to Render, and your database is already hosted (Supabase or MongoDB Atlas). You will debug deployment issues — this is where most apps break for the first time, and you will learn to fix those breakages methodically. By the end of this week, anyone in the world can open your app's URL and use it.  
2. What You Will Do This Week 
Prepare your code for production:  
Replace all http://localhost:5000 URLs in frontend with an environment variable (e.g., VITE_API_URL or NEXT_PUBLIC_API_URL). 
Remove console.log spam, but keep intentional logging. 
Set CORS on the backend to allow your production frontend URL. 
Verify .env is never committed. 
Deploy the frontend to Vercel:  
Go to vercel.com → New Project → Import your GitHub repo. 
Set the root directory if your frontend is in a subfolder. 
Add environment variables via Vercel dashboard (not CLI): NEXT_PUBLIC_API_URL pointing to your Render backend URL (which you will get in the next step). 
Click Deploy. Note the assigned URL (e.g., yourapp.vercel.app). 
Deploy the backend to Render:  
Go to render.com → New Web Service → Connect GitHub → select your repo. 
Set root directory if backend is in a subfolder (backend/). 
Build command: npm install (Node) or pip install -r requirements.txt (Python). 
Start command: npm start or uvicorn main:app --host 0.0.0.0 --port $PORT. 
Add environment variables via Render dashboard: DATABASE_URL, JWT_SECRET, OPENAI_API_KEY (or equivalent), and any OAuth secrets. 
Deploy. Note the Render URL (e.g., yourapp-api.onrender.com). 
Update frontend env var on Vercel to point to the Render URL, then redeploy. 
End-to-end test on the live URL:  
All pages load. 
Registration and login work. 
CRUD operations persist to the database. 
AI feature works. 
OAuth login completes successfully (update OAuth redirect URLs in Google/GitHub console to include the production URL). 
Debug common deployment issues:  
CORS errors: update backend CORS config to include your Vercel URL. 
Missing env vars: check Render and Vercel dashboards. 
Database connection errors: whitelist 0.0.0.0/0 in MongoDB Atlas for Render's IP range (or specific Render IPs if known); Supabase usually works out of the box. 
OAuth redirect mismatch: update callback URLs in Google/GitHub OAuth settings to match production.

5. Deliverables 
Deliverable 1: Live Public App URL 
Your app must be accessible at a public URL (Vercel URL, e.g., yourapp.vercel.app). 
All core features must work on the live URL:  
Pages load without errors 
Register / login works 
CRUD persists to the database 
AI feature functional 
OAuth login working (if implemented) 
Post the live URL. 
Deliverable 2: Deployment Documentation 
Add a section to your README:  
Live frontend URL 
Live backend URL 
Tech stack summary 
"Known limitations on free tier" (e.g., Render free tier spins down after 15 min of inactivity — first request after idle takes 30–60 sec to wake up). 
Deliverable 3: Peer Testing Feedback 
Test 2 classmates' live apps via the Forum thread. 
For each app, post 1 comment with: 1 thing that works well, 1 bug or issue you found (with steps to reproduce). 
Keep comments constructive and specific. 
Deliverable 4: Deployment Screenshots PDF 
4 screenshots:  
Vercel dashboard showing successful frontend deployment 
Render dashboard showing successful backend deployment 
Live app home page (with the URL visible in the browser) 
Live app AI feature or login flow working
