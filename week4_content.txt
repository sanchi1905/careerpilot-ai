Week 4 — Backend & API Development
1. Overview of the Week
This week you build the engine room of your app. You will set up a backend server using Express.js (Node) or
FastAPI (Python), design and implement at least 6 REST API endpoints, test every endpoint in Postman or Thunder
Client, and connect your frontend to the backend so real data flows between them. By the end of this week, your app is
no longer static — it is a full-stack app with live data.
2. What You Will Do This Week
 Initialise the backend:
o Node/Express path: Create /backend folder, npm init -y, install express, cors, dotenv, nodemon.
Create a basic server in server.js listening on port 5000.
o Python/FastAPI path: Create /backend, set up a virtual environment (python -m venv venv), install
fastapi, uvicorn, python-dotenv. Create a basic app in main.py.
 Design 6+ REST endpoints around your core data model. Example for a task manager app:
o GET /api/tasks — list all tasks
o GET /api/tasks/:id — get a single task
o POST /api/tasks — create a task
o PUT /api/tasks/:id — update a task
o DELETE /api/tasks/:id — delete a task
o GET /api/tasks/search?q=… — search tasks
 Use proper HTTP methods and status codes: 200 for successful GET/PUT, 201 for POST create, 204 for
DELETE, 400 for validation errors, 404 for not found, 500 for server errors.
 Add basic error handling middleware (Express) or exception handlers (FastAPI).
 Use in-memory data for now — a simple array or dictionary. Real database comes in Week 5.
 Test every endpoint in Postman or Thunder Client: create a collection with 6+ requests covering each
endpoint. Export the collection as a JSON file.
 Connect frontend to backend: Replace all hardcoded/mock data in your frontend with real API calls using
fetch or axios. Handle loading states (show your Loader component) and error states (show a Toast).
Configure CORS on the backend to allow your frontend origin.
3. Learning Outcomes for the Week
Week Outcome Mapped to CLO

5. Deliverables
Deliverable 1: Working REST API in GitHub Repo
 Backend folder in your GitHub repo with a clean structure.
 Minimum 6 working endpoints covering CRUD (GET list, GET single, POST, PUT/PATCH, DELETE) plus
at least one additional endpoint (search, filter, or similar).
 Each endpoint must return correct HTTP status codes and JSON responses.
 Error handling middleware/exception handlers in place.
 .env file exists but is gitignored; a .env.example file shows required env variable names.
 README updated with a "How to run backend locally" section.
Deliverable 2: Postman/Thunder Client Collection Export
 Export your API testing collection as a JSON file.
 Collection must include one request per endpoint (minimum 6).
 Each request must have a saved example response.
 File name: W4_APICollection_[InternID].json
Deliverable 3: Frontend Connected to Backend — Demo Screenshot PDF
 2–3 screenshots showing the frontend displaying data from the backend.
 One screenshot of the Network tab in Chrome DevTools showing successful API calls (status 200).
 Add brief captions under each screenshot.
 File name: W4_FrontendBackendConnection_[InternID].pdf
