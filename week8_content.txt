Week 8 — Frontend Integration & Polish 
1. Overview of the Week 
By this point all the backend layers are complete — CRUD, authentication, and the AI feature are all working. But the frontend is still largely the skeleton from Weeks 2 and 3. This week is dedicated to wiring every page and component to real backend data, completing the user-facing flows for all core features, and polishing the UI so the app looks and feels production-grade before deployment in Week 9. Every screen your user will touch must work end-to-end by Sunday. 
2. What You Will Do This Week 
Wire every page to real backend data: Replace any remaining hardcoded or mock data in your React/Next.js components with live API calls. Every list, card, and detail view should fetch from your Express/FastAPI backend. Use your Loader component during fetch and your Toast component on errors. 
Build the authenticated dashboard: Implement the main logged-in screen your user lands on after sign-in. It should display data scoped to the current user (e.g., their tasks, posts, or saved items), fetched using the JWT from the auth flow you built in Week 6. 
Complete the AI feature UI: The AI endpoint is live from Week 7 — now build the full frontend experience around it. This means a properly designed input area, a streaming or animated loading state, a well-formatted output display, and graceful error handling with user-friendly messages. 
Complete all CRUD user flows: For each resource in your app (e.g., tasks, posts, notes), ensure the full create → read → update → delete loop is accessible from the UI. Forms must validate inputs before submission. Success and error states must be shown to the user. 
Responsive polish pass: Open every page in Chrome DevTools at 375px (mobile), 768px (tablet), and 1440px (desktop). Fix any layout breaks, overflowing text, or elements that are too small to tap on mobile. Use Tailwind responsive prefixes (sm:, md:, lg:) to fix issues. 
UI/UX refinements: Review every screen against your Week 3 Figma wireframes. Fix alignment, spacing, and colour inconsistencies. Add empty-state components for lists that have no data (e.g., “No tasks yet — add your first one”). Add confirmation dialogs before destructive actions like delete. 
Error boundaries and edge cases: Add a React error boundary component to catch unexpected render errors gracefully. Test what happens when the backend is slow, returns an error, or the user is not authenticated — the app should never show a blank white screen. 
Performance check: Open Chrome DevTools → Network tab. Identify any API calls that fire repeatedly on each render. Fix unnecessary re-renders using useMemo or useCallback where appropriate. Ensure images are not oversized. 
Commit regularly: Minimum 4 commits this week with descriptive messages (e.g., “feat: wire dashboard to /api/tasks with loading state”, “fix: empty state for zero-item task list”, “feat: complete AI feature UI with streaming output”).
