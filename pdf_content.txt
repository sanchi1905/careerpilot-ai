Week 5 ΓÇö Database Design & Management
1. Overview of the Week
Your app currently uses in-memory data ΓÇö which disappears on every server restart. This week you add a
real database. You will choose between PostgreSQL (via Supabase free tier) or MongoDB (via MongoDB
Atlas free tier), design your schema, integrate an ORM/ODM, and migrate all your endpoints to use the
database for full CRUD operations.
This week also includes the Month-1 Reflection Video ΓÇô mandatory for all.
2. What You Will Do This Week
ΓÇó Choose your database:
o PostgreSQL (via Supabase): recommended if your data is structured with clear relationships (users,
posts, comments).
o MongoDB (via Atlas): recommended if your data is document-based with flexible schema (blog
posts with variable fields, chat messages, etc.).
ΓÇó Set up the database:
o Supabase: go to supabase.com, create a free project, get the database URL from Project Settings ΓåÆ
Database ΓåÆ Connection String.
o MongoDB Atlas: go to mongodb.com/cloud/atlas, create a free cluster (M0 tier), whitelist your IP,
create a database user, and get the connection string.
ΓÇó Design your schema/data model: identify 2ΓÇô3 entities (e.g., User, Task, Category), their fields,
types, and relationships. Draw this as a simple diagram (Excalidraw, draw.io, or even hand-drawn +
photo) and add it to your README.
ΓÇó Integrate an ORM or ODM:
o PostgreSQL + Prisma: npm install prisma @prisma/client, run npx prisma init, write schema
in schema.prisma, run npx prisma migrate dev to create tables.
o MongoDB + Mongoose: npm install mongoose, create model files with schemas, connect via
mongoose in your server.
ΓÇó Refactor all 6+ endpoints from Week 4 to use the database instead of in-memory data.
ΓÇó Verify full CRUD end-to-end: open your frontend, create a record, see it appear, refresh the page ΓÇö
the data should persist. Update the record, delete it, etc.
ΓÇó Store environment variables safely: database URL in .env, never committed.
